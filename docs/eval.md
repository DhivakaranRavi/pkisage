# Evaluation of the decision layer

> **Read first:** every label here was assigned by an AI assistant and has **not** been reviewed by a PKI expert. A language-model labeler may share biases with a language-model classifier, which could flatter Jev. Independent review of even 20-30 items would strengthen these numbers more than anything else.

Generated by `pkisage ai-eval` (see commands at the end). Numbers are from one run on one date; Jev is `jev-1.13.0`.

## Datasets
| Set | Items | Source | Use |
|---|---|---|---|
| **Held-out** `tests/data/heldout.jsonl` | 46 | OpenSSL 3.0 `X509_STORE_CTX_get_error(3)` messages and RFC 8555 section 6.7 problem types, each with a `source_url` | Frozen before the first evaluation (hash in `heldout.sha256`; `ai-eval --heldout` refuses a changed file). **Never tune on it.** |
| **Held-out 2** `tests/data/heldout2.jsonl` | 44 | Real GitHub issue titles with URLs | Frozen, labeled under labeling.md, evaluated once |
| **Development** `tests/data/labeled.jsonl` | 56 | Written by the developer (synthetic) | Threshold and pattern tuning |

## Results
**Jev and the rules baseline are comparable on this sample.** Their 95% intervals overlap heavily (N=46), so the difference is not statistically meaningful. The development-set scores are optimistic and are **not** the headline numbers.

| Model / set | N | Accuracy (95% Wilson CI) | Acc. excl. ambiguous | Auto-routed | Accuracy of auto-routed | Mean conf. right / wrong |
|---|---|---|---|---|---|---|
| Rules, held-out | 46 | 63.0% (48.6-75.5) | 69.2% | 13% | 83.3% | 0.16 / 0.09 |
| Jev, held-out | 46 | 71.7% (57.5-82.7) | 69.2% | 59% | 88.9% | 0.91 / 0.67 |
| Rules, development | 56 | 85.7% (74.3-92.6) | 85.7% | 68% | 97.4% | 0.71 / 0.11 |
| Jev, development | 56 | 98.2% (90.6-99.7) | 98.2% | 93% | 100.0% | 0.98 / 0.54 |

The development numbers were optimistic: accuracy on unseen, real wording is **about 72% for Jev and 63% for the rules baseline**, with wide intervals at N=46.

### Calibration, Jev on the held-out set
| Confidence bucket | N | Accuracy |
|---|---|---|
| [0.00, 0.50) | 3 | 0% |
| [0.50, 0.85) | 16 | 56% |
| [0.85, 1.00] | 27 | 89% |

Routing thresholds (bands used in this table): high >= 0.85, unverified 0.50-0.85, human < 0.50. In this run 59% were auto-routed at 88.9% accuracy, so **auto-routed errors still occur** (3 of 27). **Because of this, auto-routing is off by default**: a high-confidence classifier result is only labeled `suggested`, and sending it on without a human requires `PKISAGE_TRUST_AUTO=1`. Auto-routing is only a suggestion; the deterministic checks (preflight, logs) are what mark a diagnosis `verified`.

## Second held-out set (real GitHub issue titles)
`tests/data/heldout2.jsonl`: 44 real issue titles from public GitHub repositories (each with its `source_url`), labeled under [labeling.md](labeling.md) and frozen with a hash before evaluation. Candidates were found by keyword search on error phrases, so the set over-represents items containing those phrases; 12 are `UNKNOWN` (feature requests, advisories, unrelated). Evaluated once, with no tuning.

| Model | N | Accuracy (95% CI) | Acc. excl. ambiguous | High-confidence band | Accuracy in high band |

## Paired comparison (McNemar, exact)
Jev and the rules were run on the same items, so a paired test is used (`lab/paired.py`, output in `docs/results/paired.json`). This is a **second run** done for the paired analysis; Jev's answers can change slightly between runs (it scored 33/46 and 36/44 in the first run, 34/46 and 37/44 in the second), so the second run's results are now cached for reproducibility.

| Set | N | Jev correct | Rules correct | Jev only right | Rules only right | Both wrong | McNemar p |
|---|---|---|---|---|---|---|---|
| Held-out 1 (documentation strings) | 46 | 34 | 29 | 16 | 11 | 1 | 0.44 |
| Held-out 2 (GitHub issue titles) | 44 | 37 | 26 | 15 | 4 | 3 | 0.019 |
| Pooled | 90 | 71 (78.9%) | 55 (61.1%) | 31 | 15 | 4 | 0.026 |

Reading it: Jev is better than the rules on this data, clearly so on the GitHub titles, and not distinguishable on the documentation strings. The pooled p = 0.026 is below 0.05, but treat it carefully: it is one comparison on N=90, the labels were assigned by an AI assistant (which may share biases with an LLM-based classifier) and are not expert-reviewed, the rules baseline is a simple keyword matcher, and the two sets are different in kind. It supports "Jev outperformed the keyword baseline on these labels", not "Jev is accurate on real tickets".

## Known limitation: confident wrong answers
On feature requests, advisories and other non-error text, Jev answered with confidence 0.91-1.00 in a nearby category (for example `Gnutls security bypass accepts revoked certificates` -> `REVOKED`). Its confidence is therefore **not well calibrated for text that is not an error message**. Mitigations: auto-routing is off by default; verified diagnoses come only from deterministic checks. A "not an error message" category would be a reasonable change, but adding it needs a fresh held-out set (relabeling the frozen sets would be tuning).

## Labeling policy
The rule for `UNKNOWN` and ambiguous items is in [labeling.md](labeling.md). The frozen set was labeled under that judgement and is not relabeled; a second held-out set should apply the written rule from the start.

## Limitations (read before quoting a number)
- **Labels were assigned by the assistant that helped build the project and have not been reviewed by a PKI expert.** 7 items are flagged `ambiguous` where the mapping to our categories is a judgement call; the "excl. ambiguous" column drops them.
- **Not real tickets.** The held-out messages are documentation strings, not customer tickets, and 25 of 46 are `UNKNOWN`.
- N=46 gives wide intervals; do not read small differences as real.
- The rules baseline's ACME patterns were written after seeing Pebble output, before this set was assembled; no pattern was changed after the held-out run.

## Reproduce
```
pkisage ai-eval tests/data/heldout.jsonl --heldout --model rules
pkisage ai-eval tests/data/heldout.jsonl --heldout --model jev      # needs PKISAGE_JEV_* ; PKISAGE_NO_CACHE=1
```
